## 版本边界

| 标签 | 含义 |
| --- | --- |
| `mit-final` | 切换前最后一个整体采用 MIT 的快照，固定指向提交 `fb57ddc`。 |

## 你需要做什么

<Steps>
  <Step title="分发时提供源码">
    分发可执行版本（例如 Docker 镜像）时，按 AGPL 第 6 条提供对应源码，并保留许可证和版权声明。
  </Step>
  <Step title="提供网络服务时提供源码">
    修改本程序后通过网络向他人提供服务时，按 AGPL 第 13 条，向用户显著提供免费获取修改版对应源码的方式。
  </Step>
  <Step title="更新源码链接">
    应用界面右上角有 GitHub 源码链接。部署修改版时，把它指向你实际运行的版本的源码，而不是保留无法反映修改的上游链接。
  </Step>
</Steps>

<Warning>
  对应源码必须与实际运行的版本一致，包括你的修改以及构建、安装和运行脚本。只链接到不含你修改的上游仓库，不能满足要求。不要把 API Key、密码等部署凭据放进源码包，提供配置模板即可。
</Warning>
