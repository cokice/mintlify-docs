## What you must do

<Steps>
  <Step title="Provide source when you distribute">
    When you distribute an executable version, such as a Docker image, provide the corresponding source code under Section 6 of the AGPL. Keep the license and copyright notices.
  </Step>
  <Step title="Provide source when you offer a network service">
    When you modify this program and offer it as a service to others over a network, Section 13 of the AGPL requires you to prominently offer your users a way to get the corresponding source code of your modified version free of charge.
  </Step>
  <Step title="Update the source link">
    The app interface has a GitHub source link in the top-right corner. When you deploy a modified version, point it to the source code of the version you actually run. Don't keep an upstream link that doesn't reflect your changes.
  </Step>
</Steps>

<Warning>
  The corresponding source code must match the version you actually run, including your changes and your build, install, and run scripts. Linking only to an upstream repository that lacks your changes doesn't meet the requirement. Don't put deployment credentials such as API keys or passwords in the source package. Provide a configuration template instead.
</Warning>
